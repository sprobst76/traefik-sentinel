## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watchdog thread → SQLite | `log_watcher.process_line` runs on watchdog thread; now writes digest rows in addition to intruder_events and access_logs. |
| asyncio task → SQLite | `auto_blocker.process_intruder_event` runs as an asyncio task; adds digest writes inside the same session that commits `BlockedIP`. |
| attacker → log line | Every field in `event` (reason, ip, request_count) originates from parsed access logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Tampering (SQL) | `persist_to_digest` called from log_watcher and auto_blocker | mitigate | All args are either SQLAlchemy-parameterized (`source_id: int` from autoincrement PKs) or enum-valued strings (`source`, `severity`). Attacker-controlled strings (IP, path, reason text) are NOT passed to `persist_to_digest` — only the router-computed severity and the integer `id` from `block_ip`/`intruder.id`. |
| T-01-13 | Elevation of Privilege | auto-block bypass via crafted reason | mitigate | D-05 locks auto_blocker to always persist to digest regardless of severity. An attacker cannot force an immediate Telegram for an auto-block (which would amplify alert load under burst). Grep-enforced: no `send_alert` calls remain in auto_blocker.py. |
| T-01-14 | Elevation of Privilege | intruder-event bypass via reason spoofing | mitigate | `route_event` computes severity from the fixed `THREAT_SEVERITY` map; unknown reasons deterministically map to "medium" → digest under default. Attacker cannot promote a low-severity event to immediate. |
| T-01-15 | Denial of Service | SQLite writer contention (watchdog thread + asyncio task + digest writes) | accept | Pre-existing concurrency pattern (RESEARCH §Pitfall 3). Digest writes reuse existing sessions rather than opening new ones, minimizing contention delta. Phase 3 retention sweep bounds table growth.
