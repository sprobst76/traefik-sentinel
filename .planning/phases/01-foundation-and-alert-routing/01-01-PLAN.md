<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → app | `ALERT_MIN_SEVERITY` is operator-supplied. Untrusted in the sense that a typo or invalid value must not crash startup. |
| watchdog thread → SQLite | Digest rows written from the log watcher thread. Inputs originate from attacker-controlled access logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `app/config.py` ALERT_MIN_SEVERITY load | mitigate | Validate against allow-set `{critical, high, medium}`; on mismatch, print warning and fall back to `"high"`. Never raise. Prevents operator typo (e.g. `ALERT_MIN_SEVERITY=none`) from silently disabling alerts — the fallback guarantees critical+high still fire. |
| T-01-02 | Information Disclosure | `app/config.py` warning print | mitigate | Warning message repr()s the invalid value only. No secret env vars (BOT_TOKEN, API_KEY) are referenced in the warning path. |
| T-01-03 | Tampering (SQL injection) | `DigestEvent` writes | mitigate | All writes go through SQLAlchemy ORM (`db.add`, parameterized under the hood). No string concatenation into SQL. Attacker-controlled IP/reason/path are NOT written into `digest_events` (reference-based per DIGEST-02); only integer `source_id` and enumerated `source`/`severity` strings. |
| T-01-04 | Denial of Service | unbounded digest row growth | accept | Phase 3 adds retention sweep for `sent_at IS NOT NULL AND sent_at < NOW() - 7d`. Phase 1 growth rate is bounded by intruder event rate (same order as existing `intruder_events` table, which already has `RETENTION_INTRUDER_EVENTS_DAYS=90`). Acceptable for this phase. |
| T-01-05 | Repudiation | digest event audit trail | accept | `timestamp` recorded per row. No additional audit needed; digest events are operational metadata, not security audit records. |
</threat_model>
