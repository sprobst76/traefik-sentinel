```python
"""Digest scheduler — daily asyncio background task.

Computes next wall-clock fire time at DIGEST_HOUR:00 UTC on each iteration
(next-fire calculation, D-21). Miss policy: if started after DIGEST_HOUR today,
waits until tomorrow (D-22).

CancelledError from asyncio.sleep propagates to the caller (lifespan). Do not
suppress it here — only the send_digest() call gets try/except Exception (D-23).

Timezone: hardcoded UTC via zoneinfo.ZoneInfo("UTC") per D-26 and SCHED-05.
No datetime.utcnow() calls in this module.
"""

import asyncio
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo

from app.config import DIGEST_HOUR
from app.digest import send_digest

UTC = ZoneInfo("UTC")


def _seconds_until_next_fire(hour: int) -> float:
    """Return seconds from now until the next occurrence of `hour`:00:00 UTC.

    Always returns a strictly positive value. If `hour`:00:00 already passed today,
    returns seconds until `hour`:00:00 tomorrow (miss policy D-22).
    """
    now = datetime.now(UTC)
    target = now.replace(hour=hour, minute=0, second=0, microsecond=0)
    if target <= now:
        target += timedelta(days=1)
    return (target - now).total_seconds()


async def digest_scheduler() -> None:
    """Run the daily digest on a next-fire loop.

    Designed for asyncio.create_task(). Runs until cancelled. CancelledError from
    asyncio.sleep propagates naturally; the lifespan shutdown block suppresses it
    once (D-23). A failed send_digest() is logged but does not stop the loop.
    """
    while True:
        seconds = _seconds_until_next_fire(DIGEST_HOUR)
        next_fire = datetime.now(UTC) + timedelta(seconds=seconds)
        print(f"Digest scheduler: next fire at {next_fire.isoformat()}")

        await asyncio.sleep(seconds)  # CancelledError propagates here — do not catch

        try:
            result = await send_digest()
            print(f"Digest scheduler: send_digest completed — {result}")
        except Exception as e:
            print(f"Digest scheduler: send_digest raised exception: {e}")
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process env → app | Operator-supplied env vars (`DIGEST_ENABLED`, `DIGEST_HOUR`) cross into config & scheduler |
| scheduler task → Telegram API | Outbound HTTPS call inside `send_digest()` (implemented in Phase 2) |
| FastAPI lifespan → asyncio loop | Background task registered with the application event loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Denial of Service | `digest_scheduler` loop — unhandled exception in `send_digest()` | mitigate | `try/except Exception` around `await send_digest()` logs error and continues loop (D-23). Prevents single failed send from killing the task. |
| T-03-06 | Denial of Service | Orphaned task on shutdown (`Task was destroyed but it is pending`) | mitigate | `scheduler_task.cancel()` + `await scheduler_task` + `except asyncio.CancelledError` in lifespan shutdown (D-23, Research Pattern 3). Verified by disabled-path test. |
| T-03-07 | Tampering | `DIGEST_HOUR` env var — maliciously large/non-integer value | transfer | Plan 03-01 already validates and falls back. Scheduler trusts validated value. |
| T-03-08 | Denial of Service | Hung shutdown because scheduler suppresses `CancelledError` | mitigate | Source-level grep in acceptance criteria confirms no `except asyncio.CancelledError` / `except BaseException` inside `app/scheduler.py`. Pitfall 2 in RESEARCH.md. |
| T-03-09 | Information Disclosure | `print(f"Digest scheduler: send_digest result={result}")` logs | accept | Telegram send-outcome dict contains only aggregate counts (from Phase 2 design) — no secrets or raw attacker PII. Docker logs are operator-owned. |
| T-03-10 | Repudiation | Scheduler fires with stale `DIGEST_HOUR` if config changes at runtime | accept | Config is read at import time; operator must restart container to apply changes. Consistent with all other config in this project. |
| T-03-11 | Elevation of Privilege | Background task gaining more privileges than request handlers | accept | Task runs in the same process / same event loop / same DB session factory — no privilege boundary crossed (SCHED-04 explicitly requires this). |
</threat_model>
